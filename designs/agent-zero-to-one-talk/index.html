专题引入

Chat 是一次回答，Agent 是一段可推进的任务过程

从使用体验进入工程结构

Chat 模式

你问，我答
1
描述问题把上下文一次性交给模型
2
得到回答解释、总结、生成一段内容
3
人决定下一步继续追问、复制结果、手动执行

擅长把话说清楚；任务推进仍主要靠人接力。

差异不在
模型名字

Agent 模式

给目标，跑闭环
1
理解目标把“要达成什么”放进任务现场
2
选择行动读资料、调工具、拆计划、请求确认
3
观察结果把工具输出带回上下文继续判断
4
调整并总结反复推进，直到结果可交付

价值不是“更会聊天”，而是让复杂工作变成可观察、可控制的循环。

Loop 把一次回答变成持续推进

目标进入上下文，模型判断下一步；每次工具结果都会回到现场，再判断一次。

Context Compact

上下文总会满，要有办法腾地方

四层压缩策略：优先使用成本小的方式做处理。Harness 层负责压缩，换来干净的记忆和更长的会话。

08
System Prompt

每次发给 LLM，是结构化的完整信息

Prompt 不是写死的一段话，而是由多个 section 在运行时组装：稳定段常驻，动态段按状态加载。

左侧：System Prompt 运行时组装

11
Summary

Agent 的核心，是 Loop Engineer + Harness Engineer

Loop 让模型持续推进；Harness 给它工具、边界、上下文和外部系统。今天所有机制，基本都能放进这两类工作。

关注的是循环外的运行环境：哪些能力可用、哪些动作要确认、上下文如何维护、外部系统如何接入。
